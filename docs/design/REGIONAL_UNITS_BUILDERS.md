# Rebuilding the region-keyed data: builders, their dependencies and a run order (27 October 2026)

Read-only static analysis of `tools/build/*.py` and `tools/lib/*.py`, for the move to CAPRI's regional units
(`REGIONAL_UNITS_INVENTORY.md`). No builder, test or model code was run and no data file was changed: every statement
below comes from reading the code (and listing the existing files), so behaviour that depends on run-time data is
marked as uncertain. Companion: `REGIONAL_UNITS_INVENTORY_files.csv` (the 79 target files: `model_codes == True` and
`live == True`).

Snapshot note: `tools/build/build_regional_units.py` (writes `shared/regional_units.csv`) and a change to
`capri_mod/data/definitions.py` appeared at 05:09 while this survey was being made. That script is not one of the 114
analysed, but it is listed in section 1.1 because it is the first builder of a region list.

## 0. Summary

- **114 scripts** in `tools/build` at the start of the survey (plus the new `build_regional_units.py`) and three
  modules in `tools/lib` (`_model_regions.py`, `_capri_costsavings.py`, `paths.py`). **110** of the 114 read or write
  files under `capri_data`; the other four write `capri_reference/` (`build_capreg_tseries_reference.py`,
  `build_capri_sets_reference.py`, `build_captrd_results_reference.py`) or any path given on the command line
  (`gdx_dump_symbol.py`).
- **56 scripts** write at least one file keyed by the model's region codes (the 79 targets, the JSON files with model
  codes, and intermediate model-keyed tables under `sources/`). **43** of them write one of the 79 targets directly; two
  more run writers as sub-processes (`build_patched_inputs.py`, `build_norway_pigs.py --rebuild`; `build_shg_split.py`
  is both a writer and an orchestrator). The other ~54 scripts write files keyed by CAPRI's codes, member states or
  market regions: their outputs stay as they are and they need not be re-run for the region change.
- **74 of the 79 targets have a builder; 5 have none** (`n_deposition_regional.csv`, `fertiliser_substitution_2030.csv`,
  `livestock_intensity_bounds.csv`, `land_rent_regional.csv`, `capri_regional_n_balance_2030.csv`), as the inventory
  says. In addition, **parts of two targets have no builder**: the EU rows' `PIGS`/`PIGF` columns of
  `animal_numbers.csv` (made by `tools/build_pig_split.py`, a one-off script no longer in the repository) and the
  animal cost columns `BCOW, HFRS, CALV, PIGS, LAYS, BROI` of `variable_costs.csv` (no script writes them).
- The inventory's `builders` column (found by file name) names scripts that do not write the file for 27 of the 79
  targets (readers, or a docstring mention; in 3 cases an orchestrator that runs the writer) and misses a writer for 10
  (section 2).
- **No region list is generated by the builders that matter.** `build_capri_base.py` rewrites, in place, the rows of the
  *existing* `base_areas.csv`, `land_availability.csv`, `animal_numbers.csv`, `yields.csv`, `variable_costs.csv` and
  `sources/capreg/capreg_producer_prices.csv`; the other builders take the region list from `base_areas.csv` (most,
  through `_model_regions.model_regions()` → `capri_mod.data.loaders.load_all_data`), from `animal_numbers.csv`, or
  from an upstream model-keyed file (`yields.csv`, `cover_crops.csv`, `ammonia_tech_model.csv`, `pela_own_price.csv`,
  the crosswalk). A rebuild
  on new regions therefore starts from seeded tables (section 3, step 0).
- **Cycles: none** in the builders' file dependencies once three kinds of read are set aside: (i) the bootstrap reads
  of `build_capri_base.py` (its own outputs, for the region index and the columns), (ii) `build_nuts_crosswalk.py`'s read
  of `yields.csv`, which is used for the region list only, and (iii) comparison-only reads
  (`extract_all_from_data2.py` of `market/producer_prices.csv` and `environment/nutrient_coefs.csv`,
  `ingest_pela_gtap.py` of `supply_elasticities_regional.csv`). Counted literally, (ii) and (iii) close a cycle
  `build_nuts_crosswalk → extract_all_from_data2 → build_capri_base → … → yields.csv → build_nuts_crosswalk`.
- The ordering assumption that matters most for a from-scratch rebuild: the orchestrators' step lists
  (`build_shg_split.STEPS`, `build_norway_pigs.EXTRA_STEPS`, `build_patched_inputs.STEPS`) are written for incremental
  updates, not for a rebuild: `build_shg_split.py` runs `build_genetics_effects`, `build_lownfeed_effects` and
  `build_supplement_effects`, which read `capri_level_ratio.csv` (all three) and `cattle_intensity.csv`
  (genetics), without rebuilding those first, and it only prints a failing step's error.

Two facts about the shared helpers matter for every builder that uses them:
`capri_groups()` and `region_to_capri()` skip every CAPRI code ending in `000000`, so a country that CAPRI holds only
nationally (DK, EE, LT, LV, SI, CY, MT, HR) is in no group and always reaches CAPRI's data through the national fallback;
and both map CAPRI codes to model regions only through the correspondence file. With the model's regions renamed to
CAPRI's codes, neither function returns anything for them unless it is changed (section 4).

## 4. Open questions and uncertainties

### 4.1 Region mapping code that will not work on CAPRI's codes as it stands (read from the code, not tested)
1. `_model_regions.region_to_capri()` and `capri_groups()` map CAPRI codes to model regions only through
   `nuts_version_correspondence.json` (+ `SPLITS_MERGES`). If the model's regions become CAPRI's 8-character codes,
   neither returns anything for them, and the 37 builders that use them fall back to the member state's row without an
   error (most of them silently). Both also skip every code ending in `000000`, so the units DK000000, EE000000,
   LT000000, LV000000, SI000000, CY000000, MT000000, HR000000 would not form groups even with an identity mapping
   (build_manure_trade_base, for one, writes 0 trade for regions in no group).
2. `build_capri_base.build_spec`: its direct rule is `region + "0000"`, which fits 4-character NUTS codes only; on
   8-character codes every region falls through and the script stops at `assert not missing`. Its `RENAME`, `SPLIT`
   (cattle-share proxy), `NATIONAL`, `ZERO`, `IRELAND` and Norway tables are also the region map of
   build_crop_economics_2017, build_ghg_coefs_2017 (CO2) and build_norway_pigs (through `build_spec`), and their
   `IRELAND` / `NORWAY_*` constants are used by build_land_market, build_pmp_capri_2030 and build_animal_pmp_capri_2030.
3. Other hard-coded region handling to revisit: `COUNTRY_PREFIXES` / `PREFIX` BL→(BE, LU), IR→IE in
   build_livestock_output_coef and build_feed_ration (with CAPRI codes the Belgian, Luxembourg and Irish rows start with
   BL/IR and the national residual would not reach them); build_nh3_factors' national fallback `reg[:2] + "000000"`;
   build_histosol skipping `NO*`; build_lownfeed_effects' non-EU prefix list; build_ad_option's and
   build_ammonia_cost_curves' national-only lists; build_trajectory_model_keys' 4-character keys; the crosswalk-based
   scripts (CW drops 21 regions today).

### 4.2 Files or columns without a builder

### 4.5 Other uncertainties
13. Soft reads through `load_all_data`: nine builders call it directly and most of the 37 users of `_model_regions` call
    it through `model_regions()`; it requires `base_areas.csv`,
    `animal_numbers.csv`, `yields.csv` and `M/producer_prices.csv` and also loads ~40 optional files. I did not see a
    cross-check of region sets in the loader, but whether loading old-region optional files next to new-region base
    tables raises somewhere was not tested.
14. `build_intensity_q_2030`: the docstring says a CAPRI code mapping to several model regions gives each the same term;
    the code (`setdefault` on a dict keyed by CAPRI code) gives it to one model region. Which is intended is not clear.
15. Region-specific special cases and proxies that the move to CAPRI's units would remove (registered in the code):
    cattle-share splits (build_capri_base, through it build_crop_economics_2017 and the CO2 part of
    build_ghg_coefs_2017), Ireland's fixed shares, Norway's pooling (build_capri_base, land_market, pmp builders) and SSB
    pig shares, Saxony/Croatia crop re-splits, split parts' area-share matrices (build_land_market), orphan-parent
    detection by area sums (build_land_market), country-median q fallbacks (intensity builders, labour_setaside),
    `CORR` without fixes (build_overfert_factors), group totals spread by the model's herds (all per-head coefficient
    builders). Constants transcribed from CAPRI's GAMS code (cost tables, regressions, curbs, floors) are not
    region-keyed and stay.
16. Several builders print rather than raise when an input is missing or a step fails (build_shg_split, build_norway_pigs,
    build_intensity_q_2030 skips a missing input, many `if f.exists()` optional reads). A rebuild should check each
    script's output for the expected region count.
17. The graph treats `model_regions()`/`load_all_data` as a read of the region list only; per-builder reads listed in
    section 1 are from the code paths actually executed by default arguments; option-dependent reads (e.g. `--year`) are
    listed with their option.
