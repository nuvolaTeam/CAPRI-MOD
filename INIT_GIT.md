# Putting this on GitHub

The repository is packaging-ready: `pyproject.toml`, `LICENSE`, `CITATION.cff`,
`README.md` and `.gitignore` are in place, and the tree is 9.1 MB with no file
over 2 MB, so it is well inside GitHub's limits.

Create an empty repository on GitHub first (no README, no .gitignore — both
exist here), then:

```bash
cd capri-python
git init
git add .
git commit -m "CAPRI-Python v0.1.0

Regional PMP supply module over 248 NUTS-2 regions, Armington market
module, CAP policy instruments, environmental indicators.

Data: capreg DATA2 yields for 192 regions, regional PMP elasticities
for 132, per-column provenance tracking. Validator 11/1/0, base-year
fidelity 12/12, supply convergence 30/30, 15 tests passing."
git branch -M main
git remote add origin https://github.com/YOURNAME/capri-python.git
git push -u origin main
```

GitHub will prompt for authentication in the browser, or use the `gh` CLI.

## What .gitignore deliberately excludes

The raw CAPRI exports (`capri_export/`, `DATA2_*.txt`, `*.gdx`) are inputs to
the ingest tools, not repository content — `ALL_DATA2.txt` alone is around
129 MB, past GitHub's 100 MB per-file hard limit. Attach them to a release or
keep them outside the tree.

The `*.pre_capreg_merge` backup is also excluded; it is regenerated by the merge
tool on first run.
